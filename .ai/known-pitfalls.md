# Known pitfalls (Web)

1. **`StaleFormSessionException`.** Session answers are not per-application. File delete / upload / remove-item paths used to save without reloading API state. Two tabs → truncated `ResponseBody`. Guard lives in Application + `ExternalApiPageExceptionFilter`. Do not add a new save path that skips the guard.
2. **Health without ShortCircuit** + telemetry reading `Session` → Redis GET on every probe → restart loop when Redis is down.
3. **Single replica + Redis outage** = 100% connection refused. Prefer ≥2 web replicas in prod.
4. **`TokenRefresh:TokenEndpoint` required** even for Entra-only and Test Authentication tenants: `CompositeAuthenticationSchemeStrategy` always builds the OIDC strategy, whose token-refresh service validates `TenantTokenRefreshOptionsAccessor` (TokenRefresh, or derived from DfESignIn). The New tenant page includes it for that reason.
5. **Test Auth:** key length; Web Target overriding Shared; tenant settings written straight to the API are not seen until the Web cache expires (see 23); optional API URL rewrite to another environment.
6. **Data Protection ring** must be shared across web replicas and **not** the API ring.
7. **Forwarded headers** required behind ACA/Front Door or OIDC redirect URIs break.
8. **SignalR/Cypress** — tests disable the hub. Don’t “fix” Cypress by forcing WebSockets without the proxy.
9. **FeatureManagement Target** for Template Studio is `Web`, not `Api`/`Shared`.
10. **Upload summary blank** → FormEngine `AllowMultiple` + refresh settings. The upload **file limit** is `MaxSelections` on the same entry (see `.ai/features/form-engine.md`); it used to be ignored for uploads.
11. **Render notification text with `textContent` or a sanitiser**, never `innerHTML` on raw text. The only `innerHTML` in `notifications.js` inserts output from `/file-validation/message/render` (server `MarkdownSafe`); keep it that way.
12. **GovUK Frontend 4 rebrand** is always on — don’t fight it.
13. Redis is required for cookies/session; API can degrade to SQL. Same incident, different UX.
14. **Derived-flow uploads are not stored per item** (**Verified**, not yet fixed). Collection flows keep files per instance (`FlowProgress_{flowId}_{instanceId}`), but an upload question on a derived-flow page has no flow context in `FormFileFieldContext`, so `FormFileFieldService.GetFiles`/`SaveFiles` use one session key per application and field (`UploadedFiles_{applicationId}_{fieldId}`). Every item of that derived flow shares one file list, and the upload file limit (`MaxSelections`) counts files from all items together. Fixing it means scoping the storage key, the save path and the summary per derived item. Check whether any live template has an upload question inside a derived flow before relying on per-item files there.
15. **Application Insights host connection string is Web's own.** Web sends telemetry using its own `ApplicationInsights:ConnectionString` (Terraform hosting module sets `ApplicationInsights__ConnectionString` from the module's App Insights resource; don't also put it in `container_secret_environment_variables` or Terraform fails with a duplicate key). The API no longer sends its connection string in host-config. A tenant `ApplicationInsights` setting overrides it per request. Web only reads host-config at startup — restart after API host-config changes.
16. **Custom telemetry channel must forward the ingestion endpoint.** `Telemetry/TenantAwareTelemetryChannel.cs` wraps an inner `ServerTelemetryChannel`. The SDK applies the connection string's `IngestionEndpoint` only to the registered wrapper, so the inner host channel posted to the legacy global endpoint: browser page views arrived but server requests/traces did not. `Initialize` now sets the inner endpoint from `configuration.EndpointContainer.Ingestion`. Tenant channels were never affected. Same fix in flexforms-api.
17. **Autocomplete Enter must not reach the form.** `Views/Shared/Fields/_AutocompleteComplexField.cshtml` wraps accessible-autocomplete. Before any option is arrow-highlighted, Enter used to fall through to the page's Search submit, which cleared the typed query. Enter now prevents the default and, if no option is highlighted, clicks the first suggestion (same path as a mouse click, so `onConfirm` runs). A debug `keydown` handler that cleared the input was removed; do not reintroduce input-clearing handlers. **Verified** in code; manual browser check still advised.
18. **Client aborts are not errors.** Navigating away mid-fetch cancels `HttpContext.RequestAborted`. Catch `OperationCanceledException` only `when` that token is cancelled, log a warning without the exception object, and rethrow so `ExceptionHandlerMiddleware` records a 499. `ContributorManagementAdminService` and the Api.Client `TokenExchangeHandler` (from 0.0.55) do this. Never turn a client abort into a 401. Application Insights counts every response of 400 or above as failed, so `Telemetry/ClientAbortedRequestTelemetryProcessor` marks 499 requests `Success = true` (code kept) to keep them out of the Failures blade. The same processor exists in flexforms-api.
19. **Response bodies may be Base64 or raw JSON** depending on how the application was created. Decode with a raw fallback; see `.ai/domain-model.md` (Response envelope).
20. **User Manager is open to `User:Manage` delegates but `/v1/Roles` is Admin-only.** The role filter catches the 403 and shows only the selected role. Don't log it as a failure, and don't widen the API policy without a security decision.
21. **Concurrent requests overwrite session state** (**Verified**). ASP.NET Core session saves the whole session at the end of any request that changed it, so two overlapping requests in one session lose the earlier write. Most authenticated requests change it (`UserActivityTracker.RecordActivity`; `InternalServiceAuthenticationHandler` for service-header requests), including the background `/internal/hub-ticket` and `/notifications/unread` fetches from `notifications.js`. State kept only in session, such as the Template Studio preview (`TemplateStudioPreviewModel.SessionKey`) and TempData banners, can be lost when one of those fetches is still running. This is what made the preview Playwright tests flaky: the preview tab did not get the `window.Cypress` flag, so it ran those fetches (fixed in `PlaywrightTestBase` by setting the flag on the browser context).
22. **Template Studio panels drawn before its GOV.UK Frontend copy loads** (**Verified**). `template-studio.js` runs before the page template's GOV.UK Frontend module tags are added (they come at the end of `<body>`), so `govukFrontendUrl()` falls back to `/govuk-frontend.min.js`. That is a separate download from the page's versioned `?v=` import. The page's `initAll()` can finish while it is still loading, and an accordion drawn in that gap used to stay unstarted, with sections that would not open (this caused the flaky "Task list details" Playwright test). `enhance()` now waits for the import and starts them then.
23. **Tenant configuration is cached per Web replica** (**Verified**). `TenantConfigurationCache` and `TenantHostnameCache` are in-memory singletons, kept for `PlatformBootstrap:TenantConfigurationCacheMinutes` (default 10). A settings save used to clear only the replica that handled it, so the other replicas served old values (for example old application terminology) until expiry. The Organisation Settings, Tenant Settings (including **Refresh settings**) and Event Mappings pages now call `ITenantConfigurationInvalidator`, which clears the local caches and publishes the tenant id on the Redis channel `FlexFormsCacheKeys.TenantConfigurationInvalidatedChannel`; every replica subscribes and clears its own copy. Limits: Redis pub/sub does not queue, so a replica that is disconnected when the message is sent keeps its copy until expiry; and settings written straight to the API (scripts, Playwright API helpers, Swagger) send no message at all. Route admin changes through those pages, or call the invalidator, rather than clearing `ITenantConfigurationCache` directly — that only affects one replica.
24. **Templates and status labels use a two-level cache** (**Verified**). `ICacheService<IMemoryCacheType>` alone is per replica (the CoreLibs "hybrid" registration is two separate caches, not memory in front of Redis); the template cache and custom status labels used to live only there, and saves only cleared the replica that handled them, so other replicas served the old template for up to a day. `FormTemplateProvider` and `ApplicationStatusService` now use `ITwoLevelCache` (`Application/Interfaces`, implemented by `Infrastructure/Caching/TwoLevelCache.cs`): this replica's memory first (`CacheSettings:Memory:Durations`, 60 seconds), then Redis through `ISharedCacheStore` (`RedisSharedCacheStore`; `CacheSettings:Redis:Durations`: `GetTemplateAsync` 1 hour, `GetCustomApplicationStatusesAsync` 60 seconds), then the API. Concurrent misses on one replica share one fetch. `RemoveAsync` gives the key a new random Redis version and deletes the value, drops the memory copy and broadcasts the key on `FlexFormsCacheKeys.LocalCacheKeyRemovedChannel` so every replica drops its memory copy (it derives from `ReplicaBroadcastService`). Redis writes are versioned: a fill only writes if the version it read is unchanged, so a fetch that started before a template save cannot put the old template back in Redis, and a read that overlaps a removal is not kept in memory either. Versions must never repeat: an earlier counter (`INCR` with an expiry) could expire and be recreated at the same number a fill had already read, letting the old template through. If the Redis invalidation itself fails (Redis blip during a save), the key is retried every 5 seconds by the hosted service and, on that replica, bypasses Redis until the retry succeeds; the retry broadcasts again so other replicas drop anything they re-read from the old Redis copy after Redis recovered. Invalidation attempts are numbered and a success only clears a pending marker left by an attempt that started no later than itself; otherwise a slow successful reply could clear the marker of a later save whose invalidation failed after a refill, leaving that save's old copy in Redis. The 1-hour template lifetime bounds anything that slips past this. A replica that misses the broadcast serves its memory copy for at most the 60-second memory duration. Redis keys are `FlexForms:Cache:{<cacheKey>}` and `…:version` (hash tag, so the Lua scripts stay on one Redis Cluster slot). Redis is resolved on use, never at startup, so Web starts and serves from the API while Redis is down. Template saves, both **Clear all** handlers and status-label saves go through it (templates via `ITemplateCacheInvalidator`). Build keys with `FlexFormsCacheKeys.FormTemplate` / `CustomApplicationStatuses`; never call `Remove` on the memory or Redis cache directly for these keys, and never write them with the CoreLibs Redis cache (it writes unconditionally and would bypass the version check). A round-trip test (`FormTemplateProviderRedisTests`, real Transfers template) guards against `FormTemplate` properties that would not survive the camelCase JSON used by `RedisCacheService`; extend it when adding non-trivial template model types. Do not put new shared data in `ICacheService<IMemoryCacheType>`. The Admin home **Clear all** used to clear nothing, because it read `TemplateCacheKey` before it was set. Its cache-status diagnostic only describes the replica that served the page.
25. **Role claims must be refreshed with permission claims** (**Verified**). `PermissionsClaimProvider` adds permission and role claims with issuer `UserPermissionsCache.ClaimIssuer`. `PermissionsCacheMiddleware` strips claims with that issuer (and all `permission` claims) before re-running the transformation, because the CoreLibs transformation only adds claims. Before this, a role revoked in the last 15 seconds (the in-memory permissions TTL) could survive one more request. Add new provider claims with the same issuer, or they will not be refreshed.
26. **Do not scan the Redis keyspace from Web** (**Verified**). `ScanResultConsumer` used to run `KEYS`-style scans for `FlexForms:Cache:*{applicationId}*` and `*FlowProgress_*` on every infected file. Neither matched anything: Web keeps no application data in Redis, API cache keys are hashed, and flow progress lives inside the ASP.NET session blob, not under its own key. Both were removed; the infected-file blacklist keys (`FlexForms:InfectedFile*`) are what hide infected files.
